# KafkaBoost agent details (moved out of AGENTS.md to keep the always-loaded file small)

Read the section you need. AGENTS.md keeps the one-line version of each rule; these are the full texts, unchanged.

## Rules 11-14 (full text)
11. **Sensors:** the library comes only from the release pinned in `config/sensors.json` (a different SHA-256 means delete and refuse); nothing from it is committed; the user must agree in the app before the download; we never install a driver (CPU temperature/clock/power need the third-party PawnIO driver; without it they are *missing*, never shown as 0); never claim DPC/ISR latency (that is LatencyMon's job); the 80/90 C colors are generic, not chip-specific; any new sensor claim must be something we measured.
12. **HWiNFO on demand (Dashboard card):** proprietary freeware (non-commercial use only): never commit or bundle it. It is downloaded from the official page (https://www.hwinfo.com/download/, the "Portable for Windows 95 and later" zip, address read at run time, no pinned hash) only after the consent box, after the user was shown version, source and signer; the zip must contain `HWiNFO64.exe` and the extracted exe must have a Valid Authenticode signature from REALiX, otherwise delete and refuse. Fetch with `curl.exe` and an honest user agent (Invoke-WebRequest gets a bot-challenge page); never try to solve a challenge: a non-zip reply is `msg.hwinfo.blocked` and the user picks a zip they downloaded. Install only to `%ProgramData%LegionTuninghwinfo<version>` (admin-only ACL). `configHWiNFO64.INI` goes next to the exe before the first start; a user's own INI is never overwritten (turning `SensorsSM=1` on needs `-UpdateIni`, with a timestamped `.bak`). Start only if no HWiNFO64 from that path runs, stop only by `Path`, never with arguments. We could not confirm any session-time limit of the free edition on the official pages, so the app and docs do not state one. **Starting it for the user:** the Dashboard notice (elevated, tiles empty) says in words whether HWiNFO is missing, not running, or running with Shared Memory Support off, and its *Start HWiNFO* button is the same `hwinfo-start` step as the card (no arguments); the checkbox "Turn on Shared Memory Support in HWiNFO's INI (a backup is made)" is the only thing that sends `-UpdateIni`, ticked per start and never remembered. The setting `startHwinfoWithApp` (default off, Settings > Startup) starts an installed HWiNFO once ~15 s after the app starts (also when started hidden at logon), only if it is not running, the app is elevated and its INI **already** has `SensorsSM=1` (`autoStartDecision` in `hwinfologic.js`); it never passes `-UpdateIni`, never edits an INI, and a failure is only logged.
13. **Counter-Strike 2 preset (Optimizations > Counter-Strike 2):** no FPS promise and no anti-cheat claim (we did not test VAC; the page says so). Detection of `cs2.exe` is read-only (Steam registry, `libraryfolders.vdf`, `appmanifest_730.acf`) or a file the user picks, accepted only as a drive path named `cs2.exe` without `.`/`..` parts or wildcard characters (checked in the settings store, `main.js` and `Resolve-Cs2Exe`). The GPU preference is `HKCU\...\DirectX\UserGpuPreferences` with the previous data recorded in the shared state file (section `cs2`) and restored exactly; a preference we did not write is never reverted. The only game file written is `game\csgo\cfg\autoexec.cfg` (fixed names, never through a link, never created outside an existing cfg folder): an existing file gets a timestamped `.bak_` copy first, and restore acts only while the file carries the `// Written by KafkaBoost` marker. Only catalog ids from `config/cs2.json` are written (the one number, `fps_max`, is range checked); only cvars we are sure exist are in the catalog. Never edit Steam's `localconfig.vdf`: launch options are shown and copied for the user to paste. Disputed or placebo launch options are never ticked by default.
14. **Updates and "Apply recommended":** (a) a build that cannot update itself (source clone, portable) gets *Download and install* only when the release has `KafkaBoost-Setup-X.Y.Z.exe`; the page never supplies an address (`app:downloadUpdate` takes none); only `https://github.com/carloskafka/legion-14900hx-throttlestop/releases/download/...` and GitHub's release CDN hosts on redirects; 300 MB cap; temp file in `<temp>/KafkaBoost-update` (never Downloads); SHA-256 checked against the release's `SHA256SUMS.txt`; a mismatch deletes the file and a missing checksum file means the installer is NEVER run by the app; the installer starts only after the confirmation dialog, by `spawn(file, [], { shell: false, detached })` from that folder only, and no real installer is ever started in a test. Cleanup removes old `KafkaBoost-Setup-*.exe(.part)` / `SHA256SUMS.txt` from that folder at every start (plain files, never links). The UI says why there is no automatic update and that a clone is updated with `git pull` (no git button); SmartScreen and UAC are never bypassed. The installed build keeps `autoInstallOnAppQuit` off with one *Restart and update* path. (b) The *Apply recommended* confirmation (shared `KB.applyRecommended`) lists, per tweak, what it does, what you may notice, and the exact registry values now / new / after turning off (read-only `tweak-preview` step), admin and restart needs, and the restore-point line; the same detail is shown for advanced and risky tweaks, whose existing confirmations stay. Text is built with `textContent` only.

## Roadmap and open items
- **Built since the first version:** Settings + theme + pt-BR, tweak engine and catalog UI, Cleanup, Restore points, the Apps manager, update check with changelog, ThrottleStop on-click download, root launchers.
  **Apps manager rules:** commands are always an args array through `src/packages/runner.js` (never a shell string) and every id/query is checked against a strict per-manager regex first (`src/packages/ids.js`); only catalog ids or ids from the manager's own search can be installed; bloatware removal takes only ids from the `bloatware` allow-list of `config/apps.json` (current user only, never `-AllUsers`); import installs only ids that pass the regex and only after the user confirms the shown list; IPC `apps:*` in `main.js`/`preload.js`, UI in `renderer/js/apps.js`. **Not verified:** winget install/uninstall was never run for real, and the macOS (brew) and Linux (flatpak/apt/dnf/pacman, pkexec) code was never run; only command construction and parsing are unit-tested with a fake runner. Native Linux ids (apt/dnf/pacman) are given only where the package is in the distro's main repos; a missing id means "not offered", never a guess.
  **Counter-Strike 2 preset** (built, see rule 13): verified on the real PC only through the read-only detection (the game was found in the second Steam library, the Graphics-settings entry for it exists with `AppStatus=0;AutoHDREnable=2097;` and no `GpuPreference`, no `autoexec.cfg`); the GPU write and the `autoexec.cfg` write were **not** run for real, only against sandboxes, and nothing was checked in game (including whether CS2 runs `autoexec.cfg` by itself and whether `cl_showfps`/`fps_max` behave as described). **Built since then:** the full rename to KafkaBoost (the repo, package ids and task names keep their historical names on purpose) and the landing site on GitHub Pages (today's docs hub lives in `about-app.html`).
- **Menu names are provisional.** The sections follow the flow the TogsBoost site describes for a typical optimizer (system analysis,
  preparation, optimizations, restore). The reference video could not be analyzed (YouTube blocks automated access), so adjust the
  labels in `app/renderer/index.html` once the exact tab names are known. The old disabled placeholder cards were replaced by the tweak catalog.
- **Presets with a recommendation score** (not built): named tunings per CPU family; each with requirements (CPU generation, hybrid
  or not, VBS, laptop vs desktop), risk and source, scored against the detected system. Only the current profile is validated;
  anything from forums must be labelled unverified. The current ini is the "Default preset" for the 83DE only.
- **Live sensors** (built): the Sensors screen reads CPU/GPU/board/disk/memory sensors with LibreHardwareMonitor 0.9.6 (MPL-2.0, downloaded on demand, see rule 11 and `docs/CONFIGURATION.md`). Verified on the real PC: the download + hash check and a **non-elevated** read (78 sensors: CPU load, GPU, memory). **Not verified:** an elevated read (disk/board/fan sensors), any CPU temperature (PawnIO is not installed there), anti-cheat behaviour with that driver, and a long session (the library is reopened by a new PowerShell for every read, about 1 s each).
- **HWiNFO on demand** (built, Dashboard card): see rule 12 and `docs/CONFIGURATION.md`. Verified on the real PC: reading the official page, the portable zip download into a scratch folder (via `curl.exe`) and the Authenticode check (Valid, REALiX, version 8.54). **Not verified:** the elevated install under `%ProgramData%`, starting and stopping HWiNFO from the app, the first-start dialog of HWiNFO with the template INI, and a protection page from the site (Invoke-WebRequest was served one; `curl.exe` was not).
- **Insights** (built, Windows only; sensor source: HWiNFO shared memory): the **play session recorder** logs temperature, P/E clocks and package power every 5 s while the user plays (a manual button, or automatic when Settings > "Record play sessions automatically" is on: it checks every 10 min, starts at >= 40 W package power and stops after 30 s below 25 W). The summary gives duration, peak and average, the share of readings at PL1/PL2 and the WHEA count since start; throttle flags are not readable, and the summary says so. The last 20 sessions are kept. The **boost clock advice** is advisory only and never applies a change: it needs >= 3 loaded sessions (>= 5 min, average power >= 40 W) and answers raise (+1 ratio step only if peak <= 85 C, the clock reached the cap, under PL1, no WHEA), hold (WHEA, hot >= 90 C, marginal 86-89 C, not cap-bound, power-bound) or lowerCheck (WHEA 19 -> -80/-80/-70 mV, rule 1), or notEnough. **Not built:** a guided before/after comparison, a per-CPU-family recommendation score, and CS2 detection (automatic detection of `cs2.exe` is not built).
- Not tested on a fresh Windows install; `npm run dist` builds locally (unsigned) but `release.yml` and the Linux/macOS CI legs have never run on GitHub; the macOS/Linux code (launchers, autostart) was never run.
- FPS was never measured, only judged by feel.
- **Landing site** (built and published: the GitHub Pages deploy succeeded): `docs/index.html` + pages in EN and `pt-br/`; every number on it comes from `config/tweaks.json`, `docs/TESTING.md` or `docs/RESULTS.md` (checker enforces the first two). No FPS claims, testimonials or user counts. The repository is MIT licensed (`LICENSE`), so the site says "open source (MIT licence)"; the checker fails if a page says so while `LICENSE` is missing. ThrottleStop, HWiNFO and LibreHardwareMonitor are not covered by it and keep their own licences.
- **Still not built or never run:** the guided before/after test session, presets per CPU family, a tested release/installer on a fresh Windows install, and any Linux or macOS run (launchers, autostart, Apps providers).
